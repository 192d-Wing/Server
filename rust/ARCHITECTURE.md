# TAK-RS Architecture

Short map of the `rust/` workspace. Decisions and phases are in
[ROADMAP.md](ROADMAP.md) (§2 decisions D1–D12, §4 phases).

## Layout

```text
rust/
  Cargo.toml  Cargo.lock  rust-toolchain.toml  rustfmt.toml  clippy.toml  deny.toml
  Makefile  .gitignore  .markdownlint-cli2.jsonc
  LICENSE  NOTICE  CONTRIBUTING.md
  .cargo/config.toml  .cargo/audit.toml
  ARCHITECTURE.md  CHANGELOG.md  ROADMAP.md
  crates/          backend library crates (tak-*)
  services/        binaries (takserver, CLIs, fed-hub)
  web/             Yew/WASM apps and shared components
  scripts/         policy and CI-helper scripts
  docs/compliance/ NIST 800-53, STIG, FIPS, parity, POA&M documents
  parity/          harness that runs the Java reference server and TAKCL
  parity/corpus/   golden-corpus inputs and the Java capture driver (Phase 1a)
  fuzz/            cargo-fuzz workspace, excluded from the product workspace
```

## Dependency rules

- Web crates (`rust/web/*`) depend only on `tak-api-types` and other
  `rust/web/*` crates. They must build for `wasm32-unknown-unknown`.
- `tak-proto` and `tak-cot` also build for `wasm32-unknown-unknown`
  (`WASM_CRATES` in the `Makefile`), so the web apps can use their types.
  Their library code has no cryptography, I/O or runtime (the schema digest
  in `tak-proto/build.rs` runs on the build host only), and they must not
  depend on `tak-crypto` or any `aws-lc-*` crate.
- All cryptography and TLS goes through `tak-crypto`: rustls with a single
  `CryptoProvider` from aws-lc-rs with the `fips` feature. No other crate calls
  a crypto primitive crate. No wasm crate may reach `tak-crypto` or any
  `aws-lc-*` crate.
- The only native code is AWS-LC: `aws-lc-fips-sys` (the FIPS boundary) and,
  because rustls 0.23 `fips` pulls it in, the non-FIPS `aws-lc-sys`, which is
  linked but unused and outside the FIPS boundary (POAM-2026-10-26-08). Both
  are reachable only through `aws-lc-rs` (`deny.toml` wrappers).
- The one development-only exception is LLVM libFuzzer (C++), built by
  `libfuzzer-sys` in `rust/fuzz/` only (POAM-2026-10-27-01; see
  [Fuzz workspace](#fuzz-workspace)). It never enters the product graph.
- No crate depends on `services/*`.

## Build prerequisites

Phase 0 needs only the pinned Rust toolchain (`rust-toolchain.toml`, with the
`wasm32-unknown-unknown` target).

Phase 1a adds no tool: `tak-proto` compiles its schemas with `protox` and
`prost-build` (pure Rust), so no `protoc` binary is needed. Its build script
reads the schemas from `../src/takserver-protobuf`, so the build needs the
whole repository checkout, not only `rust/`.

Fuzzing (development only) needs `cargo-fuzz` 0.13.2 and the dated nightly
pinned in `fuzz/rust-toolchain.toml`.

From Phase 2, crates that reach `aws-lc-fips-sys` also need CMake ≥ 3.5,
Go ≥ 1.17.13, Perl 5 and a C compiler (libclang only when bindings are
regenerated). `.cargo/config.toml` forces the bundled module and forbids Go
downloads. The FIPS module builds statically only on Linux x86_64/aarch64, so
FIPS claims cover **Linux x86_64/aarch64 only**; macOS builds are for
development and tests.

## Phase 1a protocol crates

- **`tak-proto`**: prost message types for the 15 TAK Protocol schemas,
  generated by `build.rs` into `$OUT_DIR` (nothing generated is committed);
  a bounded decode (`decode_tak_message`), an encoder
  (`encode_tak_message`) and the TAK Protocol v1 stream and mesh framing
  (`framing`) as pure functions.
- **`tak-cot`**: an arena XML document with a bounded, non-recursive parser
  (on `quick-xml`) and a serializer; the `CotEvent` view; CoT XML to TAK
  Protocol v1 conversion in both directions (`to_tak_message`,
  `from_tak_message`); Java-compatible number and time formatting
  (`javafmt`); resource bounds in `Limits`; typed errors.
- Both crates use `#![forbid(unsafe_code)]`. Neither opens a socket, starts
  a runtime or touches a database, and neither library calls cryptography;
  network wiring comes in Phase 3.

### Schema digest rule

`tak-proto/build.rs` reads the schemas **in place** from
`src/takserver-protobuf/src/main/proto` and fails the build when:

- the directory or a listed schema is missing;
- the directory or a subdirectory holds a `.proto` file not in its list of
  15;
- a schema's SHA-256 differs from the committed manifest
  `crates/tak-proto/schema.sha256`;
- the compiled descriptor set holds a file that is neither listed nor a
  bundled `google/protobuf` well-known type.

An upstream schema change therefore turns the Rust build red until the
manifest gets a reviewed update (tak-protocol-reviewer).
`scripts/ci-changes.sh` routes `src/takserver-protobuf/` changes to the Rust
jobs so this check runs. The digest is a build-host change detector
(SA-10(1)), not a runtime integrity mechanism and not a FIPS function.

### Fuzz workspace

`rust/fuzz/` is a separate cargo-fuzz workspace (`exclude = ["fuzz"]` in
`Cargo.toml`). It has its own `Cargo.lock`, `deny.toml` (the product policy
plus marked `FUZZ-DELTA` blocks), `native-allowlist.txt` (only
`libfuzzer-sys`) and dated nightly toolchain. Its seven targets cover
`tak-cot` and `tak-proto` parsing, conversion, framing and `javafmt`.
`scripts/check-fuzz-policy.sh` (in `make policy`) keeps `libfuzzer-sys` and
`cc` out of the product graph and the two `deny.toml` files in step. Make
targets: `fuzz-build`, `fuzz-seeds`, `fuzz-run`, `fuzz-smoke`, `fuzz-deny`.
The `rust-fuzz.yml` workflow is never a required check. Details are in
`fuzz/README.md`.

### Golden corpus

`parity/corpus/` holds the conversion evidence for the Phase 1a exit
criterion:

```text
parity/corpus/
  MANIFEST.tsv            one row per case and direction
  .gitattributes          no end-of-line conversion
  cases/xml/              CoT XML inputs (exact bytes)
  cases/proto/            TAK Protocol inputs (.txtpb or .pb.hex)
  cases/numbers/          number and time tables
  cases/REUSE.toml        licence and provenance of the inputs
  driver/CorpusDriver.java   Apache-2.0 driver for the Java reference
```

Inputs are synthetic and written for TAK-RS. `parity/harness.sh` has the
`capture-corpus`, `verify-corpus` and `import-corpus` commands. **No goldens
exist yet**: `golden/` (the Java reference's output) is created by the
first imported capture, and the byte-for-byte golden test that compares
TAK-RS with it is not written yet. Until both exist, the Phase 1a exit
criterion is not met.

## Licence boundary

- `rust/` is Apache-2.0 (`license.workspace = true` in every member).
- `src/` is the upstream Java TAK Server under GPLv3 and is a read-only
  behavioural reference. Behaviour is derived from schemas, wire behaviour and
  black-box tests; Java is not translated line by line, and no file is copied
  from `src/` (see `CONTRIBUTING.md` §Provenance, POAM-2026-10-26-05).

## Conventions

- Every `.rs` and `.sh` file starts with `SPDX-License-Identifier: Apache-2.0`.
- `// COMPLIANCE MAPPING:` lists NIST SP 800-53 Rev 5 controls (Release 5.2.0,
  e.g. `AC-3`, `CM-2(2)`) and ASD STIG V-IDs for control implementations.
- `// PARITY: <java file>#<method>` cites the Java behaviour reference, for
  traceability only.
- `// POAM: <ID> <description>` marks an open gap tracked in
  `docs/compliance/POAM.md`; acceptance, if any, is recorded there. The
  first token after the marker must be the ID (`make policy` runs
  `scripts/check-poam-markers.sh`).
- `// SAFETY:` is required on every `unsafe` block. `unsafe_code` is
  forbidden workspace-wide; an exception needs its own `[lints]` table and
  plan approval.
- Lints: `[workspace.lints]` in `Cargo.toml` (clippy `all` deny, `pedantic`
  warn, no `unwrap`/`expect`/`panic` outside tests). CI runs with
  `-D warnings`.
